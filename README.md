# dsh-git-idea

一个把 Git 的日常操作搬进 DSH 会话里的插件：输入框左侧的仓库 chip、挂在它上面的面板
（分支树 / 提交历史 + 图 / 变更与提交 / 提交详情），以及一个 Settings 页。
Host 侧另外注册了 8 个模型工具和 22 个 RPC。

当前以**动态 Cordis 插件**的形式运行：动态插件本体只是一段「源码桥」，
真正的一半在下面这两个文件里。

## 目录

```
host.js              构建产物：Host 半侧（被桥读取并求值）—— 不要直接改
client.js            构建产物：Client 半侧（被桥读取并求值）—— 不要直接改
build.mjs            源码树 → 上面两个文件的按序拼接
src/host/*.js        Host 源码片段（9 个）
src/client/*.js      Client 源码片段（22 个）
test/                断言套件 + 性能基准
dsh-git-idea.json    （运行时生成）插件配置，默认 {initBranch:'main', cherryPickRecord:false}
bridge.log           （运行时生成）桥每次装载 Host 半侧的结果
```

`host.js` / `client.js` 的第一行就写着「GENERATED」。它们只是 `src/` 按
`build.mjs` 里那份清单顺序拼起来的结果，没有转译、没有打包、没有压缩 ——
片段之间共享同一个作用域，和当初的单文件完全一样。改代码请改 `src/`。

## 常用命令

```sh
node build.mjs            # 重新生成 host.js / client.js
node build.mjs --check    # 只检查产物是不是最新的（测试跑之前会先查这个）
node test/run-all.mjs     # 全部套件（408 条断言）
node test/bench.mjs       # 性能基准：200 个提交的历史列表
node test/bench-branch.mjs# 性能基准：300 个分支的切换器
node test/bench-watch.mjs # 性能基准：轮询签名的代价（新旧对比）
node test/build-suites.mjs# 改了 harness/body 之后重新拼出 gp37~gp41 与基准文件
```

改了源码之后要让它生效：`node build.mjs`，然后把这个动态插件 **停止再运行**
（桥在运行时会重新读文件），浏览器无需刷新。

## 界面：照 IDEA 的 Git Log 摆

三栏，每栏顶上都有自己的那一条：

```
┌ Git   变更 │ 历史 ────────────────────────────────┐
│ ┌ 搜索分支 ─┐ ┌ 搜索提交… .* Cc 分支:dev 作者 …  ⟨拣选⟩⟨还原⟩⟨标签⟩⟨分支⟩ ┐ │
│ │ HEAD/本地 │ │  图 │ 标题 │ 引用 │ 作者 │ 时间                          │ │ 选择一个提交
│ │ /远程     │ │                                                    │ │ ...
└ └───────────┘ └────────────────────────────────────────────────────┘ ┘
```

- **左栏**：顶上是分支搜索（IDEA 的 Search）。有搜索词时树强制展开、分组条数
  显示的是命中数 —— 折叠在组里的匹配等于没匹配。
- **中栏**：筛选在左、提交操作在右，中间是 IDEA 的 `.*`（正则）和 `Cc`
  （区分大小写）两个开关。两个开关默认都关，也就是改动之前的行为：字面量、忽略大小写。
  开关状态会进 `git/graph` 的参数，也进主机侧的缓存键。
- **分页**：历史一次读一页（200 条），`git log` 多要一条来判断「还有没有」；
  还有的时候列表最后一行是「已显示 N 条 · 加载更多」，点了就再要一页。
  虚拟化只画视口里的行，所以多要一页不会让浏览器多画任何东西。
- **右栏**：没选中提交时是 IDEA 的空态版式（中间一句提示，底部一句选中状态）。
- **切换分支时**：面板头部的分支 chip 和输入框上那个 chip 里的分支标记会转起来
  （`@keyframes dsh-git-spin`，只转不改尺寸，所以没有布局位移），tooltip 说「正在切到
  X…」。慢盘上一次切换好几秒，卡片早就收起了，能看见的就剩这个图标；成功或失败都会
  停下来 —— 一直转的图标比不转更糟。
- **一套记号**：同一个含义在两个列表里长得一样 —— 分组的折叠是文本 `▼`/`▶`
  （面板的 `twisty`，10px 槽位），当前分支是 `★`（面板 HEAD 行那个，不是自己发明的
  铅笔），每一行画的分支标记都相同，动作按钮用面板头部那几个字符 `⇣ ↓ ↑ +`
  （角标也只是数字，不再重复一个箭头）。同一个动作只留一种画法：`fetch`、`push`、
  `pencil` 三个没人用的图标已经从图集里删掉。**这一排只画记号，不带文字**（原来
  `⇣获取` 那样），说明进 `title`：和面板头部那几个 tool 完全一致，也省下一整行宽度。
- **收藏只有一个按钮，在头部那一排**：原来每一行行尾一颗星，用 `border` 色画在浅
  底上，几乎是看不见的；它和行首表示「当前分支」的 `★` 又是两个意思，挤在同一行里
  更容易读错。现在星在动作排里（`☆`/`★`），指的是**列表里高亮的那一行** —— 鼠标
  停在哪一行、或用键盘移到哪一行，就是它，所以「不切过去也能收藏」这条还在，按钮上
  的 `title` 会写出那个分支的名字。收藏会把那一行排到最前，而高亮记的是序号，所以
  收藏之后会按名字把高亮对回同一行（否则按钮的主语会跟着排序跑掉）。行尾只剩一个
  `›`（「这个分支能做的事」），画得比原来大一号、用可读的次级色，hover 再亮一档。
- **看哪个仓库不是面板的设置**：它是会话的工作区，由 Host 从会话解析。头部曾经还有
  一个预填着同一个路径的输入框和「应用」按钮（等于把同一件事问两遍），现在删掉了；
  头部因此一个输入框都没有。唯一的例外是工作区还不是仓库时，说明页上由人指定一次
  路径（见「一个工作区就是一个目录」）。


面板本身仍是挂在输入框上方的浮层（DSH 的面板就是这么承载的），
不是 IDEA 那种可停靠的工具窗。

设置页里输入「初始化仓库的默认分支」是一边输入一边生效的草稿，但**写文件是等
打字停下来**（400ms 合并一次）：一个字一次 RPC 加一次写盘，改个名字就是十几次。

设置页的名字是 `dsh-git-idea配置`。左栏那个图标仍由外壳给：它按 section id 挑，
只有 `models` / `agent-presets` / `plugins` 有专属字形，其余（包括我们）都退回
齿轮，而注册选项只有 `id` / `order` / `label`，没有图标这一项。**不绕路去改它** ——
把外壳自己那棵树里的字形换掉不是插件该做的事；等外壳支持了再说。

## 写操作跑在谁的沙箱里

插件的 git 命令走会话的 shell 服务。**不声明策略的调用拿到的是部署默认，不是当前
会话的策略** —— 本机上实测：部署默认是 `workspace-write`，可写根是
`/mnt/c/Users/mayou`（dsh 进程的 cwd），而这个会话本身是 `danger-full-access`。
后果很具体：任何写操作（`git` 要建 `.git/index.lock`）在别的目录上都被拒，报的是
git 的 `Permission denied`，读一切正常 —— 看起来像仓库有问题，其实是沙箱。

所以 `invoke()` 现在按会话解析策略再发出（`sessions` 找到会话、`sandboxPolicy` 解析
出该会话的 mode 与 cwd），和读者自己的命令跑在同一个沙箱里：会话是只读，插件就是
只读；会话是 danger-full-access，插件就能写它被指到的那个仓库。同一台机器上量的：

| 同一条写命令（在 /mnt/d 的仓库里建 .git 下的文件） | 结果 |
|---|---|
| 不带策略（部署默认 workspace-write） | exit=1，`denied:true`，Permission denied |
| 带上会话解析出来的策略（danger-full-access） | exit=0，`denied:false` |

策略仍然可能拒绝（会话本来就是更严的模式），那时答复里带 `sandboxDenied: true`，
面板说的是「文件沙箱不允许写这个仓库」，git 的原话留在下面 —— 不是「你的仓库坏了」。

这条规矩还要求**入参本身就带着会话**。曾经有一个地方不是：引导页的「在此初始化
仓库」走 `git/init`，它自己拼了一个只有 `repo` 的入参，`sessionId` 就这么掉了 ——
紧挨着它的那次只读探测带着策略，真正要建 `.git` 的那条命令却没有，于是它跑在部署
默认策略下，在一个读得到、写得进去的目录上回一句 `Permission denied`。现在所有
构造入参的地方都走同一个 `argsAt(input, repo)`（`repo` 和 `sessionId` 一起走），
`test/gp34a` 直接盯着 `git/init` 发出的那条命令的策略。
## 一个工作区就是一个目录

「这个工作区是不是仓库」只看**它自己**：`$dir/.git`（worktree 和子模块那里是个
文件）。不往上级目录找，也不看它的子目录 —— 之前用的是 git 自己的发现逻辑，它会
一路往上找到最近的仓库，于是：

- 工作区是 `/repo/src` 时，面板报的是 `/repo` 的分支和改动，而读者从没指着那个
  目录；
- 轮询的签名也跟着 `/repo` 的引用走，`/repo` 里任何动静都算成这个工作区的变化；
- 连 `/tmp` 里不小心留了个 `.git`，`/tmp` 下每个目录都会变成「仓库」。

现在三条命令（身份读、完整读、轮询）都以 `[ -e $dir/.git ]` 开头，里面每一步 git
调用再串 `[ -n "$gd" ]`，所以子目录会老实回答「这个目录不是 Git 仓库」，签名里也
不带楼上任何东西。目录里有什么同样不看：那个 `ls -A`（判断空目录）一并去掉了，
「空目录」不再是一种状态。

界面上也照这个结论收尾：说「这个目录不是 Git 仓库」时，页面只写标题和要看的路径，
外加「打开这个目录 / 在此初始化仓库」两个按钮 —— 没有解释规则的说明文字，也没有
让人把上面那行路径再抄一遍的输入框。输入框只在**路径本身还没定或有问题**时出现
（`no-path`、`missing`、`file`、`git-error`），那时才有东西要改。

模型工具（`git_status` 之类）保持 git 自己的语义：调用方点名要跑的命令，就按 git
的规矩跑。要不要一起收窄，等有人被它咬到再说。

## 值是值，不是选项

结构化工具把调用方给的字符串直接放进 git 的 argv：一个修订号、一个远端名、一个
分支名。以 `-` 开头的字符串已经不是那个值了 —— git 会把它当**选项**读，于是工具做着
另一件事，而且往往还是静悄悄做成的。实测（`test/gp34a` 里都有对应的断言，且要求
一个子进程都不许起）：

| 调用 | 实际跑出来的命令 |
|---|---|
| `git_sync` `branch: "--force"` | `git push origin --force`（一次没有确认的强推） |
| `git_log` `ref: "--output=/tmp/x"` | `git log … --output=/tmp/x`（把空日志写进那个文件，结果为空） |
| `git_branch` `name: "--force"` | `git branch --force` |

逃生舱工具（`git`）本来就是任意 argv，它有一套分类器管这类事；结构化工具的参数是
点名的，所以只需要一条规矩：**以 `-` 开头的值一律拒绝**，理由说清楚。`--` 之后的
东西不受影响 —— 一个叫 `-notes.txt` 的文件是正当名字，路径本来就走 `--`。

同一条规矩顺手补上了保护分支的两个缺口：`refs/heads/main`、`heads/main`、`main`
是同一个引用的三种写法，之前只认最长的那一种（`git push -f origin heads/main` 于是
只算「破坏性」而不算「禁止」）；而不给分支的强推推的是**当前分支**，当前分支同样
可能是 `main` —— 现在会先把它读出来再判。

## 性能

窗口化（只渲染滚动容器装得下的行，上下用占位块撑住高度）与行级 `memo`
（提交行、分支行、图各自成组件）之后的实测，单位是 mock-React 下单遍组件树的耗时：

| 场景 | 之前 | 之后 |
|---|---|---|
| 200 个提交，600px 视口：DOM 节点 | 1321 | 315 |
| 200 个提交：SVG 路径 | 216 | 49 |
| 200 个提交：单遍渲染 | 0.46ms | 0.10ms |
| 点一个提交后的单遍渲染 | 0.46ms | 0.14ms（memo 命中 329 次） |
| 300 个分支：单遍渲染 | 2.59ms | 0.69ms |
| 300 个分支：鼠标扫过 9 行后 | 2.20ms | 0.54ms（memo 命中 8799 次） |

页面**报不出滚动容器高度**时（测试 harness、还没布局完的浏览器）窗口化自动退化成
「全都画出来」，也就是窗口化之前的行为 —— 量不到尺寸不会让任何一行消失。

### 切换工作区为什么曾经要七秒

在真实仓库上量的（`holox_cloud`，3484 个提交，挂在 Windows 盘上）：

| | 之前 | 之后 |
|---|---|---|
| `git/panel`（面板与 chip 的第一帧） | 7044ms | **153ms**（身份读） |
| `git/watch` 每次轮询 | 7012ms | **126ms**（便宜的签名） |
| `git/watch` 只在变更页打开时 | — | 6721ms（这时才值得） |

贵的那一步是 `git status`：它要 stat 工作区里的每一个文件，在这台机器上就是
7 秒。而面板要画第一帧只需要知道「这是不是仓库、在哪个分支、有没有半途的
cherry-pick」—— 那是 0.1 秒的事（下面还有一次减半）。所以现在读两段：身份先回来、面板立刻出来，
工作区状态（改动列表、徽标数字）随后补上，两段用不同的缓存键。缓存里存的是
**正在飞的 promise**，所以 chip 的完整读和紧接着打开的面板是同一个 `git status`，
不是两个（慢盘上这就是 7 秒对 14 秒）；读到一半被失效的那一次不会把旧数据写回来，
表满时丢的是最老的一个键而不是整张表。轮询同理，
只有变更页在看着工作区时才用带 status 的签名。

两段读有个副作用要防：便宜的那段**根本没有工作区数据**，把它的「没有改动列表」
当成「没有改动」，输入框上的徽标就会在每次仓库动过之后消失、几秒后才补回来 ——
看起来就是数量丢了。所以 chip 上的数字是**最近一次真正量到的那个**，在新数字
回来之前一直留着，只是变半透明、tooltip 写着「正在核对」；同一个仓库换会话也照用
这个数字，换工作区时不会先看到一片空白（面板里的改动列表本来就保留上一次的完整读）。

### 身份读自己的形状

它只有两件事要问：这是哪个分支（连上游和领先/落后），以及有没有半途的操作。原来
是四个 git 进程：`symbolic-ref` 拿分支名、两次 `for-each-ref` 分别拿上游和领先/落后、
`rev-parse` 拿 gitdir。现在两个：

- 分支名直接读 `$gd/HEAD` 那一行。gitdir 本来就在手上，一次 `symbolic-ref` 值这条
  读的四分之一；而且它顺带回答了 `for-each-ref` 答不了的情况 —— **还没有提交的分支**
  （`refs/heads` 是空的，可 HEAD 文件里明明写着名字）。
- 上游和领先/落后由**同一次** `for-each-ref` 给出（`%(upstream:short)%1f%(upstream:track)`，
  用 `\u001f` 分隔）。分开问等于把同一张引用表重走一遍；而一次问**所有**分支更贵：
  `%(upstream:track)` 对每个分支都要跑一对 `rev-list`，同一个仓库上 109ms 对 31ms
  （那是 5 个分支的仓库）。`LC_ALL=C` 是必须的：那几个数周围的词是会被翻译的，
  而这条读正是对话框上 chip 显示的东西。

| `holox_cloud` 上的身份读（同一台机器，交替各 5 次 × 3 轮） | 耗时 |
|---|---|
| 之前（4 个进程） | 113 / 112 / 116 ms |
| 之后（2 个进程，读 HEAD 文件） | 58 / 60 / 65 ms |

### 在终端里自己切了分支，插件怎么知道

轮询签名里带着 **`.git/HEAD` 文件的内容**，不只是它的 mtime。这一点是必须的：两个
分支指向同一个提交时（`git switch -c` 永远如此，快进合并之后也一样），引用表、`HEAD`
的 sha、索引都可以逐字节相同，只有那行 `ref: refs/heads/<名字>` 能区分它们；而 mtime
只有秒级分辨率，**同一秒**里的两次切换在签名上等于什么都没发生 —— 而且此后再也不会
补上。多读一个小文件等于零成本：`holox_cloud` 上中位数 97ms → 101ms。

发现之后：**先** `git/flush` 掉主机那侧的读缓存，**再**通知每个界面重读。顺序反了
chip 读到的还是缓存里的旧分支。面板开着时快车道 3 秒，只剩 chip 时慢车道 15 秒
（两个界面共用同一个仓库的轮询器，不重复起 —— 但**没应用过仓库**时那条
「会话自己的工作区」是按会话分开的，否则一个页面上的两个会话会共用一条轮询器，
问的是最后注册那个人的工作区）；页面切到后台时不轮询，切回来的
那一刻立刻对一次签名，仓库没动就一个请求都不发。

自己切的这一路和外面切的那一路，最后都汇到同一个 `dataVersion` 计数器上，
所以 chip 和面板不会各说各的分支。

### 「面板看出来了，对话框上的图标还没动」

这条曾经真实存在，两个原因叠在一起，都是「谁在看哪个工作区」没对齐：

- **chip 轮询的工作区不跟着面板走。** 面板在引导页上「打开这个目录」之后，它自己
  的轮询换成那个目录，chip 却还在用入参 `{sessionId}`（= 会话自己的工作区，通常
  根本不是仓库），签名于是永远不变 —— 面板 3 秒一跳，chip 一动不动。现在
  `rememberRepo()` 会发一个信号，chip 的读和轮询都以它为依赖，跟着换。
- **两个界面共用一个「监听者」槽位。** `watchRepo` 把监听者存在**以回调函数为键**
  的 Set 里，而 chip 和面板要的是同一个回调（`bumpData`）：两次注册并成一条，
  先注销的那个把另一个的通知、以及以「还有没有人在看」为准的定时器一起带走。
  面板关掉时谁先谁后取决于浏览器里两个 slot root 的清理顺序，所以它是「有时候」。
  现在按**注册**（一个 token 一个键）记，注销只注销自己那一个。

测试在 `test/gp41` 里各守一条：一条真的走一遍引导页（会话工作区不是仓库 → 打开
另一个目录 → 看 chip 这一轮问的是哪个入参），一条按源码守槽位的键。两条都在改动
前的 `client.js` 上红、改动后绿。

## 读操作不抢 index.lock

一条容易踩的 Git 事实：**`git status` 会写 `.git/index`** —— 它会顺手把 stat 缓存
刷新回去，也就意味着它会去拿 `.git/index.lock`。一个每 3 秒轮询一次的插件如果不加
约束，就会持续地和用户自己的 `git add` 抢这把锁，而且输的通常是用户那条命令：
`fatal: Unable to create '…/.git/index.lock': File exists.`

所以插件里**每一条读状态的调用都带 `--no-optional-locks`**（它必须写在子命令前面）：
读就只是读，不写盘，也不拿锁。受控复现（`/tmp` 的干净仓库，一边 `git add` 跑 150 次，
一边同目录 `git status` 跑 150 次）：

| 竞争方 | `git add` 失败 |
|---|---|
| `git status`（无标志） | 15 / 150 |
| `git status --no-optional-locks` | 0 / 150 |

上报的状态两种写法完全一样，所以这个标志没有任何代价。规矩不靠记性：`test/gp34a`
里有两条防线 —— 一条在真仓库上量 `.git/index` 的 mtime（裸 status 必须能把它推动，
这是对照；插件的面板完整读取和 `git_status` 工具必须推不动），一条在源码里点名，任何
一条读状态的调用少了标志就红。

顺带清掉一个误导：**后台 auto-gc 不碰 `index.lock`**。fetch 触发的
`git maintenance run --auto` 跑的是 `pack-objects --indexed-objects` ——
`--indexed-objects` 只是**读** index 来挑要打包的对象，全程不创建 `index.lock`。
看到 `index.lock` 报错就去 gc 上找原因，方向是反的：能写 `.git/index` 的只有 index
的写者（`git add` / `commit` / `checkout` / `status` / `update-index` …）。

## 动态插件的来历与恢复

WSL 重启、进程重启都会清掉动态插件。恢复只需要重新定义一次桥（一次批准）：

- pluginId `dshgit-3`，当前包 `pkg-5`，名字 `dsh-git-idea`
- Host 半侧 = `test/gp34-bridge-host.js` 的内容
- Client 半侧 = `test/gp34-bridge-client.js` 的内容
- 桥从 `<DSH_HOME:-$HOME/.dsh>/dsh-git-idea/` 读 `host.js` 与 `client.js` 求值，
  并用 `harness.handle('dsh-git-idea/source')` 把 Client 半侧交给浏览器

两半是**同时**被派发的，而 Client 挂载的那一刻就会 `git/panel`。所以桥先等
Host 半侧装载完成才交付 Client 源码（否则面板会带着一串「未注册」的失败请求
挂上去），装载失败会重试三次并写 `bridge.log`。客户端这边另有一层保险：
`callHost()` 只对「is not registered」这一种拒绝重试（24 次 × 120ms），
其余错误一次就报出来。

`host.js` / `client.js` 的改动不需要重新批准：`node build.mjs` 之后把这个插件
停止再运行即可。只有改**桥本身**才需要新包（`pkg-6` 之类）。

`gitops` 时代的旧名字、旧 localStorage 键、旧目录都已经不再兼容：只认
`<DSH_HOME>/dsh-git-idea`，只读 `dsh.git-idea.*` 这几个键。
