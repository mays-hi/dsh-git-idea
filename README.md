# dsh-git-idea

一个把 Git 的日常操作搬进 DSH 会话里的插件：输入框左侧的仓库 chip、挂在它上面的面板
（分支树 / 提交历史 + 图 / 变更与提交 / 提交详情），以及一个 Settings 页。
Host 侧另外注册了 8 个模型工具和 24 个 RPC。

当前以**动态 Cordis 插件**的形式运行：动态插件本体只是一段「源码桥」，
真正的一半在下面这两个文件里。

## 目录

```
host.js              构建产物：Host 半侧（被桥读取并求值）—— 不要直接改
client.js            构建产物：Client 半侧（被桥读取并求值）—— 不要直接改
build.mjs            源码树 → 上面两个文件的按序拼接
src/host/*.js        Host 源码片段（9 个）
src/client/*.js      Client 源码片段（23 个）
test/                断言套件 + 性能基准
dsh-git-idea.json    （运行时生成）插件配置，默认 {initBranch:'main', cherryPickRecord:false}
bridge.log           （运行时生成）桥每次装载 Host 半侧的结果
```

`host.js` / `client.js` 的第一行就写着「GENERATED」。它们只是 `src/` 按
`build.mjs` 里那份清单顺序拼起来的结果，没有转译、没有打包、没有压缩 ——
片段之间共享同一个作用域，和当初的单文件完全一样。改代码请改 `src/`。

## 常用命令

```sh
node build.mjs            # 重新生成 host.js / client.js
node build.mjs --check    # 只检查产物是不是最新的（测试跑之前会先查这个）
node test/run-all.mjs     # 全部套件（668 条断言）
node test/bench.mjs       # 性能基准：200 个提交的历史列表
node test/bench-branch.mjs# 性能基准：300 个分支的切换器
node test/bench-watch.mjs # 性能基准：轮询签名的代价（新旧对比）
node test/build-suites.mjs# 改了 harness/body 之后重新拼出 gp37~gp42 与基准文件
```

改了源码之后要让它生效：`node build.mjs`，然后把这个动态插件 **停止再运行**
（桥在运行时会重新读文件），浏览器无需刷新。

## 界面：照 IDEA 的 Git Log 摆

三栏，每栏顶上都有自己的那一条：

```
┌ Git   变更 │ 历史 ────────────────────────────────┐
│ ┌ 搜索分支 ─┐ ┌ 搜索提交… .* Cc 分支:dev 作者 …  ⟨拣选⟩⟨还原⟩⟨标签⟩⟨分支⟩ ┐ │
│ │ HEAD/本地 │ │  图 │ 标题 │ 引用 │ 作者 │ 时间                          │ │ 选择一个提交
│ │ /远程     │ │                                                    │ │ ...
└ └───────────┘ └────────────────────────────────────────────────────┘ ┘
```

- **左栏**：顶上是分支搜索（IDEA 的 Search）。有搜索词时树强制展开、分组条数
  显示的是命中数 —— 折叠在组里的匹配等于没匹配。
- **中栏**：筛选在左、提交操作在右，中间是 IDEA 的 `.*`（正则）和 `Cc`
  （区分大小写）两个开关。两个开关默认都关，也就是改动之前的行为：字面量、忽略大小写。
  开关状态会进 `git/graph` 的参数，也进主机侧的缓存键。
- **分页**：历史一次读一页（200 条），`git log` 多要一条来判断「还有没有」；
  还有的时候列表最后一行是「已显示 N 条 · 加载更多」，点了就再要一页。
  虚拟化只画视口里的行，所以多要一页不会让浏览器多画任何东西。
- **右栏**：没选中提交时是 IDEA 的空态版式（中间一句提示，底部一句选中状态）。
- **切换分支时**：面板头部的分支 chip 和输入框上那个 chip 里的分支标记会转起来
  （`@keyframes dsh-git-spin`，只转不改尺寸，所以没有布局位移），tooltip 说「正在切到
  X…」。慢盘上一次切换好几秒，卡片早就收起了，能看见的就剩这个图标；成功或失败都会
  停下来 —— 一直转的图标比不转更糟。
- **一套记号**：同一个含义在两个列表里长得一样 —— 分组的折叠是文本 `▼`/`▶`
  （面板的 `twisty`，10px 槽位），当前分支是 `★`（面板 HEAD 行那个，不是自己发明的
  铅笔），每一行画的分支标记都相同，动作按钮用面板头部那几个字符 `⇣ ↓ ↑ +`
  （角标也只是数字，不再重复一个箭头）。同一个动作只留一种画法：`fetch`、`push`、
  `pencil` 三个没人用的图标已经从图集里删掉。**这一排只画记号，不带文字**（原来
  `⇣获取` 那样），说明进 `title`：和面板头部那几个 tool 完全一致，也省下一整行宽度。
- **收藏只有一个按钮，在头部那一排**：原来每一行行尾一颗星，用 `border` 色画在浅
  底上，几乎是看不见的；它和行首表示「当前分支」的 `★` 又是两个意思，挤在同一行里
  更容易读错。现在星在动作排里（`☆`/`★`），指的是**列表里高亮的那一行** —— 鼠标
  停在哪一行、或用键盘移到哪一行，就是它，所以「不切过去也能收藏」这条还在，按钮上
  的 `title` 会写出那个分支的名字。收藏会把那一行排到最前，而高亮记的是序号，所以
  收藏之后会按名字把高亮对回同一行（否则按钮的主语会跟着排序跑掉）。行尾只剩一个
  `›`（「这个分支能做的事」），画得比原来大一号、用可读的次级色，hover 再亮一档。
- **看哪个仓库不是面板的设置**：它是会话的工作区，由 Host 从会话解析。头部曾经还有
  一个预填着同一个路径的输入框和「应用」按钮（等于把同一件事问两遍），现在删掉了；
  头部因此一个输入框都没有。唯一的例外是工作区还不是仓库时，说明页上由人指定一次
  路径（见「一个工作区就是一个目录」）。

### 过滤之后的图：按真实历史排道

搜索框一开，普通布局就只连得上它手里的那些提交。被筛掉的父提交不在列表里，为它占的
道永远没人来认领，下一个提交于是另占一条：读者那台机器上量到过（`holox_cloud`，
`feature-risk`，搜索 `fix`，200 条匹配）——

| | 过滤时（改之前） | 过滤时（现在） | 不过滤 |
|---|---|---|---|
| 道数 / 列宽 | **14 → 202px**（真算下来 104 条道的占位，被上限压到 14） | **10 → 146px** | 8 → 118px |
| 连不到父提交的边 | **104/200（52%）**，每条只画一行就断 | **5/209（2%）**，其余按真实关系连 | 9（都是页尾） |
| 虚线边（中间隔着被筛掉的提交） | —— | **106** | 0 |
| 那次读 | 353ms | **430ms**（多读一遍这段匹配覆盖的普通历史：1518 个提交，只取 `%H %P`） | 318ms |

整屏匹配看过去像一排棒棒糖，就是这个「只画一行」造成的；圆点还会一路往右挤，最后全堆在
最后一条道上（因为上限把新道压回了 13 号）。现在有过滤时，Host 会另读一遍**这段匹配真正
覆盖的普通历史**（`git log --not <最老的那个匹配>`，只取 `%H %P`），按真实 DAG 排好道，
再把每个匹配放到它真正所在的道上；边连到最近的**可见**祖先，中间隔着被筛掉的提交时标成
**虚线** —— 这正是 IDEA 对虚线的读法，也是它开着过滤时图还是一张图的原因。连不到可见祖先
的边（这一页到头了，或者超过 `DAG_MAX`）由画面一直画到**可见的最后一行底下**，而不是在
圆点下面一行就断。

没有过滤时这条路径根本不走（`hiding` 为假就直接用原来的 `layoutGraph`），所以普通历史的
图形、道数、花费一个字节都没变。`DAG_MAX = 4000` 是给「一千个提交里才匹配一次」那种搜索
兜底的：超过它就退化成「线画到页外」，不会把一次按键变成整段历史的遍历。

钉它的是 gp34a 的 9 条（一个直线仓库：边指向最近的可见祖先、标虚线、没有可见祖先时留给
画面；一个双分支仓库：两个匹配各自的道、列宽数的是画出来的道）＋ gp37 的 7 条（实线没有
dash、虚线是 `3 3`、弯从自己的道走到父提交的道、离开这一页的线画到 y=117 而不是 91）。
**负对照**四条，各自只动一处，都只出 ✗ 不抛栈：让 Host 跳过那次真实历史读 → 6 条 ✗；
让 Host 从不标虚线 → 4 条 ✗；客户端不画 dash → 2 条 ✗；客户端退回「只画一行」→ 1 条 ✗。


面板本身仍是挂在输入框上方的浮层（DSH 的面板就是这么承载的），
不是 IDEA 那种可停靠的工具窗。

设置页里输入「初始化仓库的默认分支」是一边输入一边生效的草稿，但**写文件是等
打字停下来**（400ms 合并一次）：一个字一次 RPC 加一次写盘，改个名字就是十几次。

设置页的名字是 `dsh-git-idea配置`。左栏那个图标仍由外壳给：它按 section id 挑，
只有 `models` / `agent-presets` / `plugins` 有专属字形，其余（包括我们）都退回
齿轮，而注册选项只有 `id` / `order` / `label`，没有图标这一项。**不绕路去改它** ——
把外壳自己那棵树里的字形换掉不是插件该做的事；等外壳支持了再说。

## 看一个文件的差异

面板一直能说**哪个文件改了**：变更树是一棵树，提交详情下面是文件列表。但两处的行
都到那里为止 —— 没有任何一次读取返回过 patch，所以一个文件可以被报告成「改了」，
却永远看不到「改成什么样」。缺的不是一个列表，是一次读取和一块地方。

现在：**变更树里点任何一个文件、提交详情里点任何一个文件，patch 就占住整块正文**，
顶上一条是返回箭头、路径、增删数，右上角是 `⟳`（重读）和「暂存 / 取消暂存」。三处
决定值得写下来：

- **点一下就是看差异，不再是「只选中」**。IDEA 的提交工具窗就是这个手感：选中一个
  文件，右边就是它的差异。一行只会高亮而没有任何后续，是这块地方一直不被发现的
  原因。返回键回到列表，列表的选中状态还在。
- **差异占正文，不挤成第三栏**。左中右三栏再加一栏，剩给 patch 的宽度就读不了代码
  了。所以它是「钻进去 + 返回」，而不是一个常驻窗格。
- **`变更` 页签上带未提交文件数**。面板打开时停在历史页，一个只写着「变更」的页签
  没有任何迹象说明后面有东西等着看；数字让这件事在历史页就看得见。

四种状态，正好是两个列表可能处在的状态：

| mode | git 命令 | 用在哪 |
|---|---|---|
| `staged` | `diff --cached -- <path>` | 变更树里已在索引里的那一段 |
| `worktree` | `diff -- <path>` | 变更树里还没进索引的那一段 |
| `untracked` | `diff --no-index -- /dev/null <path>` | 变更树里的 `??`（没有 HEAD 那一侧） |
| `commit` | `show --format= --patch -m --first-parent <hash> -- <path…>` | 提交详情里的文件 |

一个文件**同时**有两段（已暂存、暂存后又改了）时，读两次、分两个小节显示，和 IDEA
一样；只有一段时只要一次读取，因为变更树的每一行本来就知道自己哪一段是空的。

几个不是装饰的参数：

- `--no-ext-diff`：用户配的 diff driver 是给编辑器看的，不是给这里看的。
- `core.quotePath=false`：中文文件名要按它本身到达。
- `-m --first-parent`（commit）：不加 `-m`，合并提交给的是**组合差异**，一次干净的
  合并结果是空的 —— 文件列表说改了，patch 说没改。
- 重命名的**旧路径一起给** git：只给新路径时 git 会把这次改动报成「新增文件」，而
  `git show --name-status` 明明说的是 `R100`。
- `--no-index` 的退出码是 **1**（「有差异」），不是错误；只有它和别的模式不一样。
- **路径必须留在仓库里**。前三种模式走 pathspec，git 自己就不会跑出工作区；第四种
  不行：`git diff --no-index -- /dev/null /etc/hostname` 会**真的读出那个文件**（在
  这条机器上量过）。所以绝对路径和 `..` 被直接拒掉，`test/gp34a` 里连着对照一起
  断言：同一条 git 命令绕过守卫确实读得出仓库外的文件，守卫是承重的。
- **不是文本的不当文本**。git 只在文件头 8000 字节里找 NUL，所以一个没有 NUL 的二
  进制会被**原样印出来**（量过：400 个随机字节变成一行 524 字符的噪声）。带 NUL 的
  和带控制字符的都只回一句「二进制」，正文丢掉。
- **不缓存**。这是给正在看的那个人读的文本：改完再读就是新的（`test/gp34a` 里对着
  真仓库验的就是这一条）。超长补丁截到 6000 行 / 400000 字符，并自报截断。

`src/client/55-diff.js` 是那块地方：patch 直接按行读成「两列行号 + 记号 + 文本」，
不引第三方 diff 库 —— 需要的东西都在文本里（`@@` 的计数决定两侧行号）。长 patch 用
的是历史列表同一套窗口化，所以几千行也只有视口那几十行在画。

## 变更树的两件事

第一件是**勾选框那一列**。原来行的缩进是行自己的 `padding-left`，而勾选框是行的第一个
孩子，于是框跟着缩进一起往右走：一层 12px，深度 5 的时候框已经在 60px 处，整列框永远
对不齐，也没法沿一条边扫下来点。从截图里量出来的（图 727px 宽、行距 42px，换算回去
正好是 12px 一层）：`holox-modules`（第 0 层）的框在 x=53，`holox-risk/src/main`（第 1
层）71，`java/…/risk`（第 2 层）89，`eval`（第 3 层）107，`domain/vo`（第 4 层）125，
最深那个文件（第 5 层）143 —— 每一步都精确地是一层。

IDEA 的提交窗不是这样：勾选框在**固定的一列**里，缩进留给右边的名字。现在也是这样：
勾选框永远是行的第一个孩子（x 固定），缩进是它后面的一个空块 `.dsh-git-tind`，宽度
`depth * 12`。测试盯住两条结构性的事实：每一行的第一个孩子都是勾选框，行自己不带
`padding-left`；顶层缩进块 0px、下一层 12px。

第二件是**被折叠的未跟踪目录**。`git status` 把未跟踪目录折叠成一行，路径以 `/` 结尾，
不说里面有什么。而 `buildTree` 是按 `/` 切段、跳过空段的 —— 于是这一整条被丢掉：

| 真实工作区（`holox_cloud`，12 处改动） | 修之前 | 修之后 |
|---|---|---|
| 树里数得出来的改动 | 10 | 12 |
| `holox-modules` 下面 | 6 个文件 | 8 个（多了 `holox-as2/` 和 `signals/`） |
| 那两个目录里的文件 | 看不见，也暂存不了 | 展开就能看、能勾 |

现在它是一个**目录行**（文件夹记号 + 结尾的 `/`）：勾选它就是 `git add -- <dir>`（整
个目录，不需要先列出内容）；展开它才去读一次，用的是
`ls-files --others --exclude-standard -z -- <dir>` —— 列的正是 `git add <dir>` 会收的
那些，`.gitignore` 同样生效，而且是一次只读的调用（`--no-optional-locks`，不写 index，
不缓存：目录是读者看它的时候最可能变的东西）。展开后的每一行就是普通的未跟踪文件行：
点开看差异、勾选暂存，和别处一模一样。

`test/gp34a` 里对着真仓库守这一条，并且留着对照：面板那一次读对同一个目录**只有一行、
末尾带斜杠、没有内容**。

### 展开未跟踪目录的那一帧会崩（真崩过一次）

`untrackedFiles[dir]` 在一次读回来之前是 **undefined** —— 展开时先把缓存的那份列表删掉，
好让行说「正在读取…」，而不是拿上一次的旧列表糊弄。但那之后循环照旧跑：

```js
const list = props.untrackedFiles[file.path]   // undefined，读还在飞
if (list === undefined) rows.push(正在读取…)
else if (list.length === 0) rows.push(（没有文件）)
for (let k = 0; k < list.length; k += 1)       // ← undefined.length
```

真实的面板就是这么掉下来的：`Cannot read properties of undefined (reading 'length')`
at `ChangesPane`，整块面板从 slot `conversation.input.overlay` 上被摘掉。窗口有多长，就是
那台机器上 `ls-files --others --exclude-standard -z -- <dir>` 有多长 —— 在 `holox_cloud`
上量：`holox-as2/` 41ms、`…/risk/eval/` 141ms、`fonts/` 77ms。短，但每一次展开都要穿过它。

测试为什么一直没看见：mock 是**立刻**回答的，`await wait(10)` 之后列表早就回来了，那
一帧从来没被渲染过一次 —— **mock 越快，越看不见这条缝**。现在 gp42 第 9 节把
`git/untracked` 扣住不回答，专门渲染那一帧（不抛异常、那一行写着「正在读取…」、松开之后
文件行照常出现），三个分支也改成了互斥（undefined / 空 / 有内容），所以这一帧再没有第二
条路可以掉下去。同一类的窗户也顺手查了一遍：会先清空再读的状态图只有这一个
（`untrackedFiles`），别处都是 `null` + `== null` 守卫。

## 变更页：两组，两个视图

IDEA 的提交窗不是一个「git 看到的东西」的大列表：上面是**变更列表**（git 管着的改动），
下面另起一个新文件的节点。这个面板以前把两者混在一棵树里 —— 未跟踪的目录就夹在被跟踪的
目录中间，唯一能分辨的办法是去读每一行的状态字母。

**判据是「HEAD 从来没有过这个路径」**，两种形状：git 还没见过它（`untracked`），或者它在
索引里是一条新增（`A…` —— porcelain=v2 打的是两位 XY，`A.` 是加了没改、`AM` 是加了又改，
所以只取第一个字母）。重命名是 `R…`，不算新文件；提交过的更不算。这一组因此叫 **新增的文件**
（原来的名字是「未跟踪的文件」，但一个已经 `git add` 过的路径并不 untracked）。

一开始判据只写了 `untracked === true && staged !== true`，于是**勾上框 = 进了索引 = 不再是
未跟踪的**，行会自己跳进变更列表：读者全选这一组，整组当场消失（「全选未跟踪文件列表，会
导致这个未跟踪文件列表消失合并到默认列表中」）。现在勾上只是框变了，行留在原地，撤出索引
也回到同一行 —— 一个可以来回切的开关。把索引里的 `A…` 也认成新文件，是这一条的全部代价：
`git add` 完 `git status` 报的就是 `A.`，没有任何别的地方记着「这是刚勾的」。提交之后它进了
HEAD，这一组自然就空了。勾一个未跟踪的**目录**仍然把它展开成里面的文件，那些文件也留在
这一组里，各自带自己的框。

**空的组不显示**（工作区真正干净的时候只有一句「工作区干净」，而不是两个空标题）。分组标题
是树里的一行，所以它守树行那条手势（单击只选中、双击或点三角折叠），**而且它带一个框** ——
IDEA 的变更列表节点也带：框放在文件行那一列框的最左边一格，点它整组进索引、再点整组出来，
半选的时候点一下就是全选。新增那一组的框点下去是整组加入索引，再点一次整组撤出。

### 「新增的文件 7 个文件」—— 数错了

git 把未跟踪的**目录**折叠成一条以 `/` 结尾的条目：那是**一个框**，底下有多少文件要展开才
知道。把它算成「1 个文件」，右边的统计就和勾选框对不上了 —— 十个框里有三个是目录，句子却写
「共 10 个文件」；而那三个目录一旦勾上，又会变成「已暂存 3 个文件」。现在文件和目录分开数
（`新增的文件 1 个文件 + 1 个目录`），暂存的比例数的是**项**（框的个数），拆解写在分组标题
和「已暂存 N / 共 M 项」的提示里。

### 未跟踪的条目有两种形状（字符串 / 对象）

Host 现在返回 `{path, code}`，但裸字符串一直是合法的，`mergeChanges` 也一直两种都认 ——
另外两个读这些列表的地方不认：它们直接读 `entry.path`，在字符串上是 `undefined`。后果有
两个，都是**按路径的那次便宜读**没了：勾上一个未跟踪目录之后，那条折叠的目录行盖不掉，和
它已经暂存的文件同时出现在列表里（量到过：框说 5 个、句子说「共 6 个文件」）；而
`pathsOfInterest` 在一棵全是未跟踪路径的树上会回答「没有要问的路径」，把 0.5s 的那次读变回
7.4s 的整棵 `git status`。三处现在都走同一个 `entryPath()`。

| 真实工作区（`holox_cloud`，`feature-risk` @ `b54041a48`，此刻 `git status` 量的） | 这是什么 |
|---|---|
| 默认变更列表 | 3 个文件（都是工作区改动，索引里一个都没有） |
| 新增的文件 | 4 个文件 + 3 个 git 折叠掉的目录（7 项） |
| 页签上的「变更 N」 | 10 项 |

第二个开关是 IDEA 的另一个按钮：**树 / 扁平**。同一批行、同样的框、同样的手势，差别只有
标签和缩进 —— 树视图按目录折叠，扁平视图每个文件一行，而且**按路径排序**：git 自己的顺序
是「索引、工作区、未跟踪」，那不是谁选的顺序。这个选择存在这个浏览器的偏好里
（`dsh.git-idea.settings` 的 `changesView`，默认 `tree`），重开面板还在；未跟踪目录在扁平
视图里照样是能展开的一行，展开出来的文件也照样跟着它。

**扁平行是「名字在前，目录压暗跟在后面」。** 一开始写成了 `目录/ + 名字`，于是一条 120 字的
路径先把自己铺满，行尾被裁掉的正好是文件名 —— 截图里那一行是
`.../risk/eval/service/impl/` 加上 `SignalClusterEvalReportServiceIm…`：名字被只为说明它在
哪儿的路径挤出了边缘。现在读作 `SignalClusterEvalReportServiceImpl.java` + 压暗的
`holox-modules/…/impl/`（单独一格 `.dsh-git-tpath`，8px 之外字号小一号、颜色降一档），
树视图不重复目录 —— 层级本身就是那条路径。

**这个开关住在面板头部**，和页签、同步按钮、分支同一行，而且**只在变更页出现**（历史页上它
什么都切不了）。它以前在列表上方单独占一行：两个词花掉列表一整行的高度。那一行连同右边的
「已暂存 N / M」一起没了 —— 后者提交面板上本来就有，于是列表从面板顶端开始，行多了一行的
高度。

钉住它的是 gp42 第 10 节 23 条（21 条行为 + 2 条样式规则）：两组各带自己的条数、顺序是变更列表在前、未跟踪组里没有
被跟踪的文件、目录树只出现在变更列表组里、扁平视图没有目录行而名字在前目录在后、按路径
排序、开关在头部且不在列表里、切过去写进偏好、重新挂载面板仍然是扁平、切回来目录行回来
且不重复目录，以及分组标题守同一条手势；再往后 2 条钉「开关只在变更页出现」。第 11 节
（16 条）钉一组的全选框、「数字数的是什么」，以及**勾上之后行留在原地**；第 12 节（5 条）钉
未跟踪条目的两种形状；第 13 节（13 条，见「勾一下，只动那一行」）钉一行在被
勾的那一刻到底动了什么。
**负对照**（九条，各自只动一处，都是**只出 ✗、不抛栈**）：把名字与目录换回目录在前 →
3 条 ✗；让开关在每一页都出现 → 「历史页没有这个开关」✗；把那一行工具条加回列表上方 →
「住在面板头部」✗；拿掉 `margin-left:auto` → 它不再被推到最右端 ✗；把 `.dsh-git-tpath` 的
颜色换成一级色 → 目录不再压暗 ✗；把分组标题的框去掉 → 10 条 ✗；让组框永远是空的 →
2 条 ✗；把两个读未跟踪列表的地方换回 `entry.path` → 2 条 ✗（只换 `pathsOfInterest` → 1 条 ✗）；
**把分组判据换回 `untracked && !staged` → 6 条 ✗**（勾上之后整组消失的那几条）。

刻意没做：**真正的多个变更列表**（IDEA 那种可以新建、命名、在列表之间搬文件的）。git 没有
changelist 这个概念，做它要自己存一份列表、还要处理「搬进另一个列表时索引怎么动」。现在的
映射是「一个列表 = 未提交的改动」，索引与工作区的区别落在勾选框和状态字母上。

### 勾一下，只动那一行

「还是有点闪动」—— 一帧一帧量过（把 mock 扣住不回答，逐帧渲染），闪的是三处，都不是点击
本身：

| 闪什么 | 为什么 | 现在 |
|---|---|---|
| 整个面板暗一下 | 勾选抬了面板级的 `busy`，而 `busy` 让头部四个工具和提交按钮按 40–45% 不透明度渲染，提交按钮的字还换成「处理中…」（宽度一变右边整块跟着动）。`git add` 在这台机器上是 98–236ms | 勾选不再抬 `busy`：框动了就是全部反馈。提交按钮不再靠禁用挡，改由**改动队列**保证它排在勾选后面 |
| 那一行自己往前跳 | `mergeChanges` 的次序来自 git 回答的列表（索引在前、工作区次之、未跟踪最后），于是位置说明了条目来自哪个列表。量到：三个新文件里勾第二个，这一组从 `[tmp.bin, zztail.bin, newdir/]` 重画成 `[zztail.bin, tmp.bin, newdir/]` | 两组都**先按路径排序**：次序只由路径决定，勾选之间不会有人挪窝 |
| 取消勾选时跳进另一组再跳回来 | `stageLocally`「回到未跟踪」那一支比的是整串 `indexCode === 'A'`，而 Host 报的是两位的 `A.`／`AM`（同一份代码里 `isNewFile` 走的是首字母）。于是取消勾选被预测成「工作区改了」，行先落进默认变更列表，等读回来才跳回去 | 两处问同一个问题：`addedInIndex()` 只取首字母，分组和取消勾选都用它 |

**改动是排队的，一次一个。** 这不只是顺序问题：并发的 `git add` 会互相抢 `.git/index.lock`，
在 `/tmp` 里量过一次 —— **39 个并发 add，29 个**直接死在 `Unable to create '.git/index.lock':
File exists`。面板每点一个框就是一条 `git add`，所以快速连点本来就会有一半左右失败、框自己
翻回去。现在点击按顺序排队，提交排在它前面那次勾选后面（那半下「禁用」正是闪的一半）。只有
最新那次点击的确认读可以落笔：旧回复描述的索引已经被后来的点击推翻，画上去就是把框按回原处。

钉住它的是 gp42 第 13 节 13 条：两组按路径排序、勾上与取消勾选三帧里行序都不动、取消勾选
预测成「回到未跟踪」、那一刻面板没变暗（没有工具被禁用、按钮没变「处理中…」）、按路径的确认
读还在且只问这一条、提交排在勾选之后；再加 1 条钉「是不是新增」只有一个读法。
**负对照**（四条，都只出 ✗、不抛栈）：去掉按路径排序 → 3 条 ✗；勾选又抬 `busy` → 5 条 ✗；
把 `addedInIndex` 换回整串比较 → 12 条 ✗；让队列不再排队 → 「提交还没发出去」✗。
（并发的量法：`for i in $(seq 2 40); do git add -- f$i.txt & done; wait`。）

## 树行的手势

**单击只选中；展开/折叠要么双击整行，要么点它左边的那个三角**（IDEA 的项目树就是这个
手势）。这看着像口味，其实是上面那两件事的另一面：单击就展开的话，「只选中这一行」在树里
根本不存在 —— 点哪儿树都动，看起来像点错了东西；而未跟踪目录的展开要多读一次目录内容
（那一次 `ls-files`），单击顺手把它带走，等于每次只是想选中都多付一次读。

逐行查了一遍之后：

| 行 | 单击 | 双击 / 三角 | 钉在哪 |
|---|---|---|---|
| 目录行（变更树、提交详情的文件树） | 只选中 | 展开/折叠 | `gp42` 第 8 节 20 条 |
| 未跟踪目录行（git 折叠掉的那种） | 只选中，**一次 `git/untracked` 都不发** | 读一次并列出文件 | 同上 |
| 分支行（历史页左边） | 只选中 | 双击才把历史切到它 | `gp37` |
| **分组标题（HEAD / 本地 / 远程 · x）** | 只选中 | 展开/折叠 | `gp37` 新增 11 条 |
| 文件行 | **单击就看差异** | —— | `gp42`（提交窗口里选中即预览） |
| **分组标题最左边的那个框** | 整组进/出索引（半选 → 全选） | —— | `gp42` 第 11 节 12 条 |

第四行是这次唯一改掉的行为：它原来是整棵树里唯一「单击就折叠」的行 —— 点了树就动、选中
却没动。现在它和目录行共用同一个三角控件（`44-twisty`，它自己会 `stopPropagation`，所以
点三角不会顺手把选中挪过来）。

两处刻意留着不动，因为它们没有「选中」这个状态可言：**文件行**的单击就是看差异（IDEA 的
提交窗口也是选中即预览），**切换分支卡片**里的分组头是菜单项，单击折叠是它唯一的动作。
（分组标题左边那个框不是一个例外：它自己 `stopPropagation`，所以点框不会顺手选中那一行 ——
第 11 节专门有一条钉这件事。）

手势里最容易写错的一处是**真实的双击**：浏览器会先送两次 `click`，再送一次 `dblclick`。
所以未跟踪目录那一条断言是按真实顺序发的（两次 `onClick` + 一次 `onDoubleClick`），
要求只读一次 —— 一次双击两次目录读，是这个手势最容易漏掉的代价。

## 写操作跑在谁的沙箱里

插件的 git 命令走会话的 shell 服务。**不声明策略的调用拿到的是部署默认，不是当前
会话的策略** —— 本机上实测：部署默认是 `workspace-write`，可写根是
`/mnt/c/Users/mayou`（dsh 进程的 cwd），而这个会话本身是 `danger-full-access`。
后果很具体：任何写操作（`git` 要建 `.git/index.lock`）在别的目录上都被拒，报的是
git 的 `Permission denied`，读一切正常 —— 看起来像仓库有问题，其实是沙箱。

所以 `invoke()` 现在按会话解析策略再发出（`sessions` 找到会话、`sandboxPolicy` 解析
出该会话的 mode 与 cwd），和读者自己的命令跑在同一个沙箱里：会话是只读，插件就是
只读；会话是 danger-full-access，插件就能写它被指到的那个仓库。同一台机器上量的：

| 同一条写命令（在 /mnt/d 的仓库里建 .git 下的文件） | 结果 |
|---|---|
| 不带策略（部署默认 workspace-write） | exit=1，`denied:true`，Permission denied |
| 带上会话解析出来的策略（danger-full-access） | exit=0，`denied:false` |

策略仍然可能拒绝（会话本来就是更严的模式），那时答复里带 `sandboxDenied: true`，
面板说的是「文件沙箱不允许写这个仓库」，git 的原话留在下面 —— 不是「你的仓库坏了」。

这条规矩还要求**入参本身就带着会话**。曾经有一个地方不是：引导页的「在此初始化
仓库」走 `git/init`，它自己拼了一个只有 `repo` 的入参，`sessionId` 就这么掉了 ——
紧挨着它的那次只读探测带着策略，真正要建 `.git` 的那条命令却没有，于是它跑在部署
默认策略下，在一个读得到、写得进去的目录上回一句 `Permission denied`。现在所有
构造入参的地方都走同一个 `argsAt(input, repo)`（`repo` 和 `sessionId` 一起走），
`test/gp34a` 直接盯着 `git/init` 发出的那条命令的策略。
## 一个工作区就是一个目录

「这个工作区是不是仓库」只看**它自己**：`$dir/.git`（worktree 和子模块那里是个
文件）。不往上级目录找，也不看它的子目录 —— 之前用的是 git 自己的发现逻辑，它会
一路往上找到最近的仓库，于是：

- 工作区是 `/repo/src` 时，面板报的是 `/repo` 的分支和改动，而读者从没指着那个
  目录；
- 轮询的签名也跟着 `/repo` 的引用走，`/repo` 里任何动静都算成这个工作区的变化；
- 连 `/tmp` 里不小心留了个 `.git`，`/tmp` 下每个目录都会变成「仓库」。

现在三条命令（身份读、完整读、轮询）都以 `[ -e $dir/.git ]` 开头，里面每一步 git
调用再串 `[ -n "$gd" ]`，所以子目录会老实回答「这个目录不是 Git 仓库」，签名里也
不带楼上任何东西。目录里有什么同样不看：那个 `ls -A`（判断空目录）一并去掉了，
「空目录」不再是一种状态。

界面上也照这个结论收尾：说「这个目录不是 Git 仓库」时，页面只写标题和要看的路径，
外加「打开这个目录 / 在此初始化仓库」两个按钮 —— 没有解释规则的说明文字，也没有
让人把上面那行路径再抄一遍的输入框。输入框只在**路径本身还没定或有问题**时出现
（`no-path`、`missing`、`file`、`git-error`），那时才有东西要改。

模型工具（`git_status` 之类）保持 git 自己的语义：调用方点名要跑的命令，就按 git
的规矩跑。要不要一起收窄，等有人被它咬到再说。

## 值是值，不是选项

结构化工具把调用方给的字符串直接放进 git 的 argv：一个修订号、一个远端名、一个
分支名。以 `-` 开头的字符串已经不是那个值了 —— git 会把它当**选项**读，于是工具做着
另一件事，而且往往还是静悄悄做成的。实测（`test/gp34a` 里都有对应的断言，且要求
一个子进程都不许起）：

| 调用 | 实际跑出来的命令 |
|---|---|
| `git_sync` `branch: "--force"` | `git push origin --force`（一次没有确认的强推） |
| `git_log` `ref: "--output=/tmp/x"` | `git log … --output=/tmp/x`（把空日志写进那个文件，结果为空） |
| `git_branch` `name: "--force"` | `git branch --force` |

逃生舱工具（`git`）本来就是任意 argv，它有一套分类器管这类事；结构化工具的参数是
点名的，所以只需要一条规矩：**以 `-` 开头的值一律拒绝**，理由说清楚。`--` 之后的
东西不受影响 —— 一个叫 `-notes.txt` 的文件是正当名字，路径本来就走 `--`。

同一条规矩顺手补上了保护分支的两个缺口：`refs/heads/main`、`heads/main`、`main`
是同一个引用的三种写法，之前只认最长的那一种（`git push -f origin heads/main` 于是
只算「破坏性」而不算「禁止」）；而不给分支的强推推的是**当前分支**，当前分支同样
可能是 `main` —— 现在会先把它读出来再判。

### 切换工作区为什么曾经要七秒

在真实仓库上量的（`holox_cloud`，3484 个提交，挂在 Windows 盘上）：

| | 之前 | 之后 |
|---|---|---|
| `git/panel`（面板与 chip 的第一帧） | 7044ms | **153ms**（身份读） |
| `git/watch` 每次轮询 | 7012ms | **126ms**（便宜的签名） |
| `git/watch` 只在变更页打开时 | — | 当时 6721ms（见下一节：现在按路径问） |

贵的那一步是 `git status`：它要 stat 工作区里的每一个文件，在这台机器上就是
7 秒。而面板要画第一帧只需要知道「这是不是仓库、在哪个分支、有没有半途的
cherry-pick」—— 那是 0.1 秒的事（下面还有一次减半）。所以现在读两段：身份先回来、面板立刻出来，
工作区状态（改动列表、徽标数字）随后补上，两段用不同的缓存键。缓存里存的是
**正在飞的 promise**，所以 chip 的完整读和紧接着打开的面板是同一个 `git status`，
不是两个（慢盘上这就是 7 秒对 14 秒）；读到一半被失效的那一次不会把旧数据写回来，
表满时丢的是最老的一个键而不是整张表。轮询同理，
只有变更页在看着工作区时才用带 status 的签名。

两段读有个副作用要防：便宜的那段**根本没有工作区数据**，把它的「没有改动列表」
当成「没有改动」，输入框上的徽标就会在每次仓库动过之后消失、几秒后才补回来 ——
看起来就是数量丢了。所以 chip 上的数字是**最近一次真正量到的那个**，在新数字
回来之前一直留着，只是变半透明、tooltip 写着「正在核对」；同一个仓库换会话也照用
这个数字，换工作区时不会先看到一片空白（面板里的改动列表本来就保留上一次的完整读）。

### 勾选框点下去没反应，和「每次轮询 7 秒」是怎么加起来的

同一个仓库、同一台机器上量的数（每个都是当场跑出来的）：

| 一条命令 | 耗时 |
|---|---|
| `git status --porcelain=v2 --branch --untracked-files=normal`（整棵树） | 7.4s（冷 13.6s） |
| 同上 `-uno` / `--untracked-files=all` | 5.3s / 13.0s |
| **同一条命令，只问变更页正在显示的那 36 个路径** | **0.5s** |
| `git add -- <一个文件>` / `git restore --staged -- <一个文件>` | 98–236ms |
| `for-each-ref`（旁边那条便宜读）单独跑 / 整树 status 正在跑时 | 50ms / 143ms |

于是读者报的三件事各自有了出处：

- **点一下框没反应**：`git add` 只花 0.2 秒，可框是从**随后那次整树读**画出来的 ——
  7.4 秒。点下去等七秒，和点下去什么都没发生是同一件事。现在框从点击本身画出来
  （`stageLocally`：按行上已有的信息把它挪进/挪出索引），`git/stage` 回来后按
  **这些路径**确认一次（0.5s）；git 拒绝的话把上一份快照放回去，并把 git 的原话显示出来。
- **重新打开就丢了**：一次读要几秒，读者在这期间点了框；那份**已经在飞的**读描述的是
  点击之前的索引，画上去正好把刚点的框擦回原样。现在每个工作区有一个 epoch
  （`repoEpoch`），任何改动都把它 +1，带着旧 epoch 回来的回答直接丢掉。
- **分支面板也卡**：深读每 3 秒跑一次整树 status，而它自己要 7.4 秒 —— 探针比间隔还长，
  挂载就没有休息的时候；旁边那条 `for-each-ref` 从 50ms 变成 143ms，别的读也跟着排队。
  现在深读**按路径问**：面板把「屏幕上这些路径 + 它们所在的目录」交给 watcher
  （`setWatchPaths` → `git/watch` 的 `paths`），签名里就只剩这些路径的状态。

`git/panel` 与 `git/watch` 因此都能带 `paths`：主机侧每个路径都过 diff 那道关卡
（相对路径、不出仓库、无 NUL），条数封顶 200（pathspec 列表就是一条命令行），答案
自报 `partial: true` 并带回问过的路径，客户端把这些条目折进屏幕上那份快照
（`mergePanelStatus`），而不是拿它当整棵树。

**代价写在明处**：屏幕上的路径、它们所在的目录、索引、引用和 HEAD 仍然是几秒内就
看见；而「一个本来干净的文件、在没人看着的目录里被改了」只有整树读看得见，所以它
落在面板自己的时钟上（`FULL_STATUS_MS = 30s`）、刷新键、以及提交/切换这类仓库级操作
之后 —— 30 秒内一定看见，通常更快（新文件出现在已经改过的目录里，3 秒内就看见）。

### 身份读自己的形状

它只有两件事要问：这是哪个分支（连上游和领先/落后），以及有没有半途的操作。原来
是四个 git 进程：`symbolic-ref` 拿分支名、两次 `for-each-ref` 分别拿上游和领先/落后、
`rev-parse` 拿 gitdir。现在两个：

- 分支名直接读 `$gd/HEAD` 那一行。gitdir 本来就在手上，一次 `symbolic-ref` 值这条
  读的四分之一；而且它顺带回答了 `for-each-ref` 答不了的情况 —— **还没有提交的分支**
  （`refs/heads` 是空的，可 HEAD 文件里明明写着名字）。
- 上游和领先/落后由**同一次** `for-each-ref` 给出（`%(upstream:short)%1f%(upstream:track)`，
  用 `\u001f` 分隔）。分开问等于把同一张引用表重走一遍；而一次问**所有**分支更贵：
  `%(upstream:track)` 对每个分支都要跑一对 `rev-list`，同一个仓库上 109ms 对 31ms
  （那是 5 个分支的仓库）。`LC_ALL=C` 是必须的：那几个数周围的词是会被翻译的，
  而这条读正是对话框上 chip 显示的东西。

| `holox_cloud` 上的身份读（同一台机器，交替各 5 次 × 3 轮） | 耗时 |
|---|---|
| 之前（4 个进程） | 113 / 112 / 116 ms |
| 之后（2 个进程，读 HEAD 文件） | 58 / 60 / 65 ms |

### 在终端里自己切了分支，插件怎么知道

轮询签名里带着 **`.git/HEAD` 文件的内容**，不只是它的 mtime。这一点是必须的：两个
分支指向同一个提交时（`git switch -c` 永远如此，快进合并之后也一样），引用表、`HEAD`
的 sha、索引都可以逐字节相同，只有那行 `ref: refs/heads/<名字>` 能区分它们；而 mtime
只有秒级分辨率，**同一秒**里的两次切换在签名上等于什么都没发生 —— 而且此后再也不会
补上。多读一个小文件等于零成本：`holox_cloud` 上中位数 97ms → 101ms。

发现之后：**先** `git/flush` 掉主机那侧的读缓存，**再**通知每个界面重读。顺序反了
chip 读到的还是缓存里的旧分支。面板开着时快车道 3 秒，只剩 chip 时慢车道 15 秒
（两个界面共用同一个仓库的轮询器，不重复起 —— 但**没应用过仓库**时那条
「会话自己的工作区」是按会话分开的，否则一个页面上的两个会话会共用一条轮询器，
问的是最后注册那个人的工作区）；页面切到后台时不轮询，切回来的
那一刻立刻对一次签名，仓库没动就一个请求都不发。

自己切的这一路和外面切的那一路，最后都汇到同一个 `dataVersion` 计数器上，
所以 chip 和面板不会各说各的分支。

### 「面板看出来了，对话框上的图标还没动」

这条曾经真实存在，两个原因叠在一起，都是「谁在看哪个工作区」没对齐：

- **chip 轮询的工作区不跟着面板走。** 面板在引导页上「打开这个目录」之后，它自己
  的轮询换成那个目录，chip 却还在用入参 `{sessionId}`（= 会话自己的工作区，通常
  根本不是仓库），签名于是永远不变 —— 面板 3 秒一跳，chip 一动不动。现在
  `rememberRepo()` 会发一个信号，chip 的读和轮询都以它为依赖，跟着换。
- **两个界面共用一个「监听者」槽位。** `watchRepo` 把监听者存在**以回调函数为键**
  的 Set 里，而 chip 和面板要的是同一个回调（`bumpData`）：两次注册并成一条，
  先注销的那个把另一个的通知、以及以「还有没有人在看」为准的定时器一起带走。
  面板关掉时谁先谁后取决于浏览器里两个 slot root 的清理顺序，所以它是「有时候」。
  现在按**注册**（一个 token 一个键）记，注销只注销自己那一个。

测试在 `test/gp41` 里各守一条：一条真的走一遍引导页（会话工作区不是仓库 → 打开
另一个目录 → 看 chip 这一轮问的是哪个入参），一条按源码守槽位的键。两条都在改动
前的 `client.js` 上红、改动后绿。

## 读操作不抢 index.lock

一条容易踩的 Git 事实：**`git status` 会写 `.git/index`** —— 它会顺手把 stat 缓存
刷新回去，也就意味着它会去拿 `.git/index.lock`。一个每 3 秒轮询一次的插件如果不加
约束，就会持续地和用户自己的 `git add` 抢这把锁，而且输的通常是用户那条命令：
`fatal: Unable to create '…/.git/index.lock': File exists.`

所以插件里**每一条读状态的调用都带 `--no-optional-locks`**（它必须写在子命令前面）：
读就只是读，不写盘，也不拿锁。受控复现（`/tmp` 的干净仓库，一边 `git add` 跑 150 次，
一边同目录 `git status` 跑 150 次）：

| 竞争方 | `git add` 失败 |
|---|---|
| `git status`（无标志） | 15 / 150 |
| `git status --no-optional-locks` | 0 / 150 |

上报的状态两种写法完全一样，所以这个标志没有任何代价。规矩不靠记性：`test/gp34a`
里有两条防线 —— 一条在真仓库上量 `.git/index` 的 mtime（裸 status 必须能把它推动，
这是对照；插件的面板完整读取和 `git_status` 工具必须推不动），一条在源码里点名，任何
一条读状态的调用少了标志就红。

**差异读（`git/diff`）也要带这个标志，而且这里量到的东西值得写清楚**：`git diff`
偶尔会写 `.git/index` —— 在 `touch f` 把 stat 缓存弄过期之后，裸 `git diff` 20 次里
**2 次**重写了 index，带 `--no-optional-locks` 的 20 次里 **0 次**，而裸 `git status`
是 **20/20**。手按一个 `.git/index.lock` 在那里，三者都照样退出 0（git 对刷新失败
是安静的），所以「按住锁」不是个能测出差别的手段；一边 120 次 `git add`、一边 120 次
`git diff` 对撞，两边也都是 0 次失败。真正会撞上锁的是那条**偶发**的写入。

这件事的教训一半在测试上：**「跑一次、比 mtime」测不出这种偶发写入** —— 带标志的读
在 Node 那一侧也被观察到过 1 次（约十次套件运行一次），于是那条断言改成了钉 argv：
四种模式的命令里，标志都在子命令前面（确定性），而 mtime 的比法只留给 `git status`
那种每次都写的路径（对照组 20/20，面板完整读取和 `git_status` 工具 0 次）。

顺带清掉一个误导：**后台 auto-gc 不碰 `index.lock`**。fetch 触发的
`git maintenance run --auto` 跑的是 `pack-objects --indexed-objects` ——
`--indexed-objects` 只是**读** index 来挑要打包的对象，全程不创建 `index.lock`。
看到 `index.lock` 报错就去 gc 上找原因，方向是反的：能写 `.git/index` 的只有 index
的写者（`git add` / `commit` / `checkout` / `status` / `update-index` …）。

## 动态插件的来历与恢复

WSL 重启、进程重启都会清掉动态插件。恢复只需要重新定义一次桥（一次批准）：

- pluginId `dshgit-3`，当前包 `pkg-5`，名字 `dsh-git-idea`
- Host 半侧 = `test/gp34-bridge-host.js` 的内容
- Client 半侧 = `test/gp34-bridge-client.js` 的内容
- 桥从 `<DSH_HOME:-$HOME/.dsh>/dsh-git-idea/` 读 `host.js` 与 `client.js` 求值，
  并用 `harness.handle('dsh-git-idea/source')` 把 Client 半侧交给浏览器

两半是**同时**被派发的，而 Client 挂载的那一刻就会 `git/panel`。所以桥先等
Host 半侧装载完成才交付 Client 源码（否则面板会带着一串「未注册」的失败请求
挂上去），装载失败会重试三次并写 `bridge.log`。客户端这边另有一层保险：
`callHost()` 只对「is not registered」这一种拒绝重试（24 次 × 120ms），
其余错误一次就报出来。

`host.js` / `client.js` 的改动不需要重新批准：`node build.mjs` 之后把这个插件
停止再运行即可。只有改**桥本身**才需要新包（`pkg-6` 之类）。

`gitops` 时代的旧名字、旧 localStorage 键、旧目录都已经不再兼容：只认
`<DSH_HOME>/dsh-git-idea`，只读 `dsh.git-idea.*` 这几个键。

## 还没做的

搬成**正式插件包**（`package.json` + `lib/` + `client/`，装进 profile）。那样就不再需要
桥，插件随部署一起升级；迁移要点见同目录之外的研究笔记（`REAL-PLUGIN-API.md`）。

两件这一轮明确没做的事，都记在这里而不是留给下次重新发现：

- 整棵树的那次读仍然是**走树**：git 没有别的办法回答「一个本来干净的文件被改了」。
  原生文件监视（inotify / `ReadDirectoryChangesW`）会把它变成事件，但 `/mnt/d` 这类
  挂载上事件不可靠，所以答案是「屏幕上的路径按需读 + 整树按时钟读」，而不是假装有通知。
- 按路径的答案只覆盖那些路径（`partial`）：屏幕外**新出现**的改动要等下一次整树读
  （≤30s）。要让它立刻可见，有一条便宜的路可走 —— `git diff --cached --name-only`
  是索引侧的读（同机实测 `git diff --cached --quiet` 81ms，与走树的 6.3s 相对），
  可以把「刚被暂存的、屏幕上看不见的路径」补进同一次确认。现在没做，因为 30 秒的
  整树时钟已经把窗口封住了，而那条读要再拼一次答案的形状。
